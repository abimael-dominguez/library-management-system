## Project Overview

This project provides the backend foundation for a scalable Library Management System (LMS), built using Python and Django, and designed to expose data via Django REST Framework (DRF).

The core strength of this system is its normalized database schema, which ensures high data integrity by accurately tracking inventory and separating book information from physical copies.

## Features

- **Normalized Database Schema**: Separates book metadata from physical copies for accurate inventory control.
- **Comprehensive Models**: Supports books, copies, members, employees, and loan transactions.
- **RESTful API**: Built with DRF for easy integration with frontends.
- **Scalable Design**: Suitable for small to large-scale library operations.
- **Data Integrity**: Foreign keys and constraints ensure reliable data management.

## Technology Stack

- **Backend Framework**: Python / Django
- **API Layer**: Django REST Framework (DRF)
- **Database**: PostgreSQL (Recommended) or SQLite/MySQL

## Architecture

The system follows a normalized relational database design with five core entities:

- **Book**: Stores metadata for book titles.
- **Book Copy**: Tracks individual physical items.
- **Member**: Manages library patrons.
- **Employee**: Handles staff involved in processing.
- **Loan**: Records borrowing transactions.

This separation allows for precise inventory tracking and prevents data anomalies.

## Database Schema Definition

This section outlines the five core models and their fields, data types, and notes.

### 1. book (Metadata for the Title)

This table stores unique information about a book title, not the physical copies.

| Field Name       | Description                          | Data Type / Notes                  |
|------------------|--------------------------------------|------------------------------------|
| id               | Primary Key (PK)                     | Auto-generated by Django.          |
| title            | The name of the book.                 | CharField (Max 255)                |
| author           | The main author.                     | CharField (Max 255)                |
| isbn             | International Standard Book Number.  | CharField (Max 17, Unique)         |
| publisher        | The publishing house.                | CharField (Max 255)                |
| publication_year | The year the book was published.     | IntegerField                       |
| genre            | The book's genre (e.g., Fiction, Science). | CharField (Max 100)                |
| total_copies     | Calculated Property                  | Derived: Counts all records in the book_copy table linked to this book. (Replaces inventory count). |
| available_copies | Calculated Property                  | Derived: Counts linked book_copy records where status is 'available'. |

### 2. book_copy (Physical Inventory Item)

This table tracks every individual physical book on the shelf, which is crucial for inventory control.

| Field Name | Description                          | Data Type / Notes                  |
|------------|--------------------------------------|------------------------------------|
| id         | Primary Key (PK)                     | Auto-generated by Django.          |
| book_id    | Foreign Key (FK)                     | Links to the book table (Title Metadata). |
| status     | Current physical state and availability. | CharField (Choices: 'available', 'loaned', 'damaged', 'lost') |

### 3. member (Library Partners)

Stores user information for library patrons.

| Field Name         | Description                          | Data Type / Notes                  |
|--------------------|--------------------------------------|------------------------------------|
| id                 | Primary Key (PK)                     | Auto-generated by Django.          |
| first_name         | Member's first name.                 | CharField (Max 100)                |
| last_name          | Member's last name.                  | CharField (Max 100)                |
| address            | Member's mailing address.            | CharField (Max 255)                |
| phone              | Contact phone number.                | CharField (Max 20, Optional/Nullable) |
| email              | Member's email address.              | EmailField (Unique)                |
| registration_date  | Date the member joined.              | DateField (Auto-set on creation)   |
| status             | Member's account status.             | CharField (Choices: 'active', 'inactive', 'suspended') |

### 4. employee (Library Staff)

Stores information about staff members involved in loan processing.

| Field Name  | Description                          | Data Type / Notes                  |
|-------------|--------------------------------------|------------------------------------|
| id          | Primary Key (PK)                     | Auto-generated by Django.          |
| first_name  | Employee's first name.               | CharField (Max 100)                |
| last_name   | Employee's last name.                | CharField (Max 100)                |
| position    | Employee's job title.                | CharField (Max 100)                |

### 5. loan (Transaction Record)

Records every instance of a book copy being loaned out.

| Field Name          | Description                          | Data Type / Notes                  |
|--------------------|--------------------------------------|------------------------------------|
| id                 | Primary Key (PK)                     | Auto-generated by Django.          |
| book_copy_id       | Foreign Key (FK)                     | Links to the book_copy table (The physical item). |
| member_id          | Foreign Key (FK)                     | Links to the member table (The borrower). |
| employee_id        | Foreign Key (FK)                     | Links to the employee table (The processor, set to NULL on employee deletion). |
| loan_date          | Date the book was borrowed.          | DateField (Auto-set on creation)   |
| due_date           | The estimated return date.           | DateField                          |
| actual_return_date | The actual return date.              | DateField (Optional/Nullable)      |
| status             | Current state of the transaction.    | CharField (Choices: 'in_progress', 'returned', 'overdue') |

## Getting Started

### Prerequisites

- Python 3.11 or higher
- Django 4.2 or higher
- PostgreSQL (recommended) or SQLite/MySQL
- Git

### Installation

1. Clone the repository:

   ```bash
   git clone https://github.com/abimael-dominguez/library-management-system.git
   cd library-management-system
   ```

2. Create a virtual environment:

   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. Install dependencies:

   ```bash
   pip install django djangorestframework psycopg2-binary  # Add psycopg2 for PostgreSQL
   ```

### Setup

1. Create a Django project and app:

   ```bash
   django-admin startproject library_project .
   python manage.py startapp library_app
   ```

2. Copy the model definitions from `models.py` into your app's `models.py` file.

3. Generate and apply migrations:

   ```bash
   python manage.py makemigrations library_app
   python manage.py migrate
   ```

4. Create Django REST Framework Serializers for data interaction.
